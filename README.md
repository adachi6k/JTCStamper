# JTC Stamper — 最小実装

**Just To Confirm — 確認した、その記録を。**

JTCは「Just To Confirm」の略です。

Windows用の日付印アプリ。C# / .NET 10 / WPF。

## 配布版

迷った場合は**通常版（推奨）**を選んでください。

| 版 | EXEサイズ | 必要な実行環境 | 配置先 |
|---|---:|---|---|
| 通常版 | 約63.4MiB | 同梱 | `dist/win-x64` |
| 軽量版 | 約1.8MiB | .NET 10 Desktop Runtime x64を別途導入 | `dist/lite-win-x64` |

どちらも`JTCStamper.App.exe`ひとつで、機能と保存形式は共通です。`publish-all.cmd`で両方ビルドできます。[配布版の選び方と更新手順](docs/DISTRIBUTION.md)を参照してください。両配布版のWindows実機起動は未確認です。

## 起動

Windows x64では、`start.cmd`を実行してください。`publish`内にランタイム同梱のビルド済みアプリを用意しています（Windows実機では未検証）。

ソースから起動する場合は.NET 10 SDKをインストールして`run.cmd`を実行します。

```powershell
dotnet run --project src/JTCStamper.App -c Release
```

`publish/JTCStamper.App.exe`を直接起動することもできます。

## 実装した機能

- 赤い印影のプレビュー、氏名・任意の日付・下段文字の変更。
- PNGクリップボード出力（Bitmap互換形式も登録）。
- 生成ごとのUUID、生成UTCと表示日付の分離、生成・コピー要求・コピー結果の記録。
- HMAC-SHA256の連鎖履歴、DPAPI CurrentUserによる鍵保護。
- 生成履歴一覧、元記録を変更しない注釈追記。
- 完全なイベントID・HMACを持つ`.jtc`原本の保存。
- 保存失敗時はコピーを成功扱いにしない。

履歴と鍵は実行ファイルの隣にある`journal`フォルダーと`key.dpapi`へ保存します。保存先は選んだEXEを置いたフォルダーです。書込みできない場合は［履歴 → 保存先を選択］で変更できます（選択は今回の起動中のみ）。コピー完了の記録は貼付完了を意味しません。

## 未実装・未検証

画像からの印影探索・類似検索、原本照合、12-bit幾何コードの生成・復号は試験実装済みです。EMF、Office経由の実機検証、原本の履歴への取込、暗号化バックアップ・移行UIは次段階です。最小版で模倣検出ができるという意味ではありません。Windowsの画面・DPAPI・クリップボードは実機動作確認が必要です。

鍵を失うと既存履歴のHMACを検証できません。DPAPI鍵ファイルだけの別PCコピーでは移行できません。正式運用前にバックアップ・復元機能を実装して検証してください。

## 印面設定と画面

［ファイル］から氏名・表示日付・下段文字を`.jtcstamp`ファイルに保存・読込できます。読込時の日付は当日に戻します。設定ファイルには秘密鍵や生成履歴を含めません。

印面の日付は`'26.09.18`のように西暦下2桁とアポストロフィで表示します。履歴・設定・原本には4桁の年を保持します。文字は字形の範囲を基準に、円と区切り線の内側へ最大限収めます。名称とタグラインはタイトルバーとバージョン情報で確認できます。

更新時は`publish/journal`と`publish/key.dpapi`を削除しないでください。保存場所が移動しても、DPAPIの別PC移行制約は変わりません。

## アプリアイコンとショートカット

採用した「JTC＋印」の丸印をEXEとウィンドウに設定しています。開発フォルダーの`JTC Stamper.lnk`から起動でき、デスクトップへコピーできます。ショートカットはこのPCの配置場所を参照するためGit管理対象外です。フォルダー移動後は`publish/JTCStamper.App.exe`からショートカットを作り直してください。

## 起動時の診断

起動時の例外はダイアログと実行ファイル隣の`startup-error.log`に記録します。書込み不可なら一時フォルダーの`JTCStamper`へ保存します。ウィンドウ用PNGアイコンの読込失敗は`icon-error.log`に記録し、本体の起動を続けます。

## 日付の運用

通常はPCのローカル日付（当日）を使用し、日付欄は編集できません。［日付を指定…］を押すと過去・未来の日付を指定でき、画面に「指定日」と表示します。［当日に戻す］で通常運用へ戻ります。

当日モードは日付をまたいだ後も追従し、ウィンドウを再度アクティブにしたときとコピー直前にも確認します。指定日モードでは指定した日付を維持します。起動時・印面設定の読込時は必ず当日モードです。設定ファイルのDisplayDateは保存時の値として残しますが、読込時に自動適用しません。

現在の12-bit方式と合成画像評価の結果は[docs/RING12-CODE.md](docs/RING12-CODE.md)を参照してください。

対応する印影は現在の12-bit形式のみです。非対応形式の原本は拒否し、履歴の非対応記録は照合対象から除外します。保存済みの履歴・鍵の自動削除は行いません。

円周の半透明化については[アルファブレンディング比較](docs/ALPHA-COMPARISON.md)を実施しました。小さいJPEGでの復号率低下を確認したため、現在は完全な欠け方式を維持しています。

[円周＋横線4か所の色コードと16ビット化の比較](docs/COLOR-LINE-COMPARISON.md)を追加しました。16ビットの試験実装はPNGで復号できましたが、小さいJPEGへの耐性が不足しているため製品版には未適用です。

通常操作はメイン画面の［作成］［照合］［履歴］タブで切り替えます。照合画像・結果はタブ間で保持し、照合結果から該当履歴を開けます。

照合結果は、完全一致、コードと形の候補、形のみの候補、候補なし、比較不能を区別して表示します。「形の近さ」は確率ではありません。[結果の読み方](docs/VERIFICATION.md)を参照してください。

# JTC Stamper 設計 v0.1

正式名称は **JTC Stamper**。JTCは **Just To Confirm** の略。タグラインは「確認した、その記録を。」。

## 目的と境界

個人PCの生成履歴と印影を照合し、独自に作られた模倣印影を見分ける補助をする。本物の印影の無断コピーの検出、本人性の証明、法的な電子署名、第三者向けの真正性保証は対象外。中央サーバーは不要。

表示日付は任意の過去・未来。生成時刻はUTCのOS時刻を別項目で保存する。PC時計は利用者が変更可能で、信頼されたタイムスタンプではない。

## 構成

C# / .NET 10 / WPFを採用する。CoreはOSに依存しない履歴・モデル・コピー制御、AppはWPF描画・画面・Windowsクリップボード・DPAPI、Checksは障害系のコンソールテスト。最小版の画面はコードビハインドで薄く接続し、画面増加時にViewModelへ移す。

印影は96×96の論理座標、赤い外円と2本の区切り線と3つの文字領域で描画する。PNGは384×384px / 384dpi、背景透過。印影外側は通常の透明な余白のみで、情報を埋め込まない。氏名と下段文字は16文字以内、領域幅に収めて縮小する。最小フォントサイズや長い氏名の可読性は実機評価で調整する。

現在は区切り線を水平に描く。PoCの画像を切り貼りする処理は製品に入れない。後続で共通のStampScene（円・線の端点・文字アウトライン・物理寸法）を抽出し、WPF/PNGとEMFの同一形状出力へ進める。

## 最小版の記録とコピー

1. 入力検証、PNG生成。プレビューだけではイベントを作らない。
2. 新しいUUIDを発行し、Generatedを永続化。表示日付、生成UTC、氏名、下段文字、描画バージョン、PNG SHA-256を含める。
3. CopyRequestedを永続化。
4. WindowsクリップボードへPNGとBitmap互換形式を一度に登録し、永続化指定する。
5. API成功後にCopyCompletedを永続化してから成功表示。貼付完了とは表示しない。
6. API失敗時はCopyFailedを追記。結果保存失敗時は成功扱いせず、内容がクリップボードに残る可能性を表示する。

「生成してPNGコピー」を押すたびに別のイベントIDとする。履歴からの再コピーは未実装で、追加時は元イベント参照を持った新しい生成イベントとする。

コピーとファイル保存を単一トランザクションにはできない。Generatedのみ、またはCopyRequestedで途切れた記録は「コピー未完了／不明」。クラッシュ後も成功と推定しない。保存前の失敗ではクリップボードAPIを呼ばない。

## データとHMAC

標準保存先は `AppContext.BaseDirectory`（実行ファイルの隣）。配布版は`publish`内。書込みできないときはコピーを停止し、メニューから明示的に別の保存先を選択できる。選択はセッション中のみで、起動時は常に標準保存先とする。自動移動・統合・削除は行わない。

- `key.dpapi`: CSPRNGの256-bit HMAC秘密鍵をWindows DPAPI CurrentUserで保護。
- `journal/000000000001.json` 以降: 連番の不変レコード。各レコードにバージョン、連番、前レコードMAC、種別、完全なイベントID、記録UTC、ペイロードを保持。
- `.jtc` 原本: Generatedの署名付きレコードをそのまま保存するJSON。完全なイベントID、描画仕様、PNGハッシュ、HMACを含み、秘密鍵は含めない。

HMAC-SHA256の対象はEntryJsonのUTF-8バイト列。JSONを読み戻して再直列化せず、保存した文字列そのものを検証する。注釈はAnnotationAddedとして独立して追記し、Generatedは更新しない。

書込みは同一ディレクトリの一時ファイルをFlush(true)した後、上書き禁止のリネームで確定する。最小版ではプロセス生存期間中の排他ファイルで同時起動を拒否する。起動時・読込時・追記前に全件HMACと連鎖を検証。不正ならコピーを停止し、自動で修復・再初期化しない。鍵がなく履歴が残っている場合も新しい鍵を発行しない。

HMACは鍵を持たない者の編集や中間削除を検知できるが、同一Windowsユーザー権限の攻撃者による鍵利用、管理者による改変、ログ末尾削除、履歴全体の巻戻しは防げない。外部アンカーなしに完全なロールバック検出は保証しない。ファイルシステム・電源断によるディレクトリメタデータの永続性も実機試験が必要。大量履歴では全件再検証が遅くなるため、後続で検証済み索引を追加するが、索引を真実の原本にしない。

現行原本は描画パラメーターとPNGハッシュを持ち、PNG本体・フォントは埋め込まない。別環境で同一画素の再生成は保証しない。製品形式v2ではPNG本体および文字アウトラインを含む原本コンテナーを検討し、ハッシュと照合する。原本ファイルの照合UIは実装済み。履歴への取込は未実装。

## 鍵のバックアップ・ログ移行（設計、UIは未実装）

DPAPIファイルの単純コピーは別PC移行の方法としない。通常運用前にポータブルな暗号化バックアップを実装し、復元テストを通す。

提案形式: バージョン、ランダムsalt、KDF名とパラメーター、nonce、AES-256-GCM暗号文、認証タグ。パスフレーズからPBKDF2-HMAC-SHA256で鍵を導出（初期候補600,000反復、実機で負荷評価）。暗号化対象は履歴鍵・key ID・journal一式・連番/MACの最終値・マニフェスト。アルゴリズムと形式バージョンはAADで保護。毎回独立salt/nonceを使う。復号時のKDFパラメーターには上限を設ける。

移行手順: アプリの書込みを止める→全履歴検証→暗号化バックアップ作成→別媒体へ保管→移行先の一時領域へ復号→全件HMACと終端を検証→秘密鍵を移行先CurrentUserでDPAPI保護→空の保存先へ確定→再読込確認。既存ログへの混在や上書きは行わない。複数鍵を扱うときはkey IDごとのアーカイブに分離し、GeneratedのIDとMACを保持する。移行元を破棄する前に件数・注釈・原本検証を照合する。

暫定的にアプリ終了後の保存フォルダー一式をバックアップできるが、DPAPIを復号できる同じWindowsプロファイルの存続が前提。パスフレーズやWindowsプロファイルを失った場合の復旧保証はない。秘密鍵を原本やクリップボードへ含めない。

## 画像照合と幾何コード

円内の28セルに12-bitのペイロードと形式マーカー・CRCを描画する。コードは履歴検索の候補キーであり、HMACと同じ認証強度はない。4096通りの値から完全なイベントIDを復元したとは表示しない。詳細はRING12-CODE.mdを参照。

照合の流れ: 印影領域指定または探索→元画像の赤色強度を評価→円内セルの濃淡・形式マーカー・CRCで棄却→候補コード→検証済み履歴候補→日付・文字・全体形状の整合性を追加評価。

結果の語彙:

| 結果 | 条件と意味 |
|---|---|
| 一致する生成履歴あり | 原本ならHMACと完全IDが履歴に一致。画像なら候補・他特徴との整合が閾値を満たす。画像由来か原本由来かを併記し、候補数を示す。本人性・無断コピーでないことは証明しない。 |
| 一致記録なし | 読取品質と履歴の検証が十分で、調査したローカル履歴に候補がない。偽造とは断定しない。別PC、削除、未移行などもあり得る。 |
| 判定不能 | 低品質、棄却角度、領域探索失敗、候補の曖昧さ、ログ不正、鍵欠損など。 |

コードが衝突しただけで「一致する生成履歴あり」にしない。正規印影をコピーした画像は元履歴に一致し得るが、これは対象外の挙動として説明する。

## EMF・Office

次段階でWin32のCF_ENHMETAFILEによるクリップボード登録を実装する。共通シーンの円・線・文字アウトラインからEMFを生成し、GDIオブジェクトとハンドル所有権を明確に管理する。PNG/Bitmap/EMFを登録した後、アプリ終了後も貼り付くこと、実寸、透明背景、文字、上下線の角度を確認する。Officeが選ぶ形式はアプリ・バージョン・貼付方法に依存するため、指定形式貼付と通常貼付を分けて評価する。

## 初回フィードバック反映

描画版は`wpf-v4-ring12`。日付表示は先頭アポストロフィ付き`yy.MM.dd`、保持値はDateOnlyで4桁年。文字はBuildGeometryで字形を取り出し、可視境界を円内側半径36と区切り線からの間隔に収めて一様拡大する。過去の生成記録のRenderer値は変更しない。

画面上部の大きな名称を廃止し、ファイル・履歴・ヘルプメニューとステータスバーを配置。印面設定はバージョン付きJSON（`.jtcstamp`）に独立保存する。必須項目と長さを検証してから画面へ反映し、一時ファイル＋リネームで保存する。これは編集可能な設定であり、認証付き原本とは区別する。

## 当日を標準とする日付操作

StampDateSelectionは未指定時に利用時点のローカル日付を返す。指定日は明示操作のときだけ保持し、当日に戻すと解除する。表示は15秒間隔とウィンドウ再アクティブ化時に同期し、生成・コピー時は利用時点の日付を使う。指定日モードは日付をまたいでも保持する。

設定ファイルはVersion 1のみを扱う。読込モデルではDisplayDateを保持するが、画面への適用では氏名と下段文字を復元し、日付モードを当日に戻す。過去の設定で意図せず過去日付をコピーすることを防ぐ。

現在の12-bit形式以外の描画・復号・移行・互換比較は実装しない。非対応の原本は明示的に拒否し、履歴ではHMACを検証した後に形式マーカーで対象を選別する。保存済みファイルの自動削除・上書き・変換は行わない。

# 検証計画と実行結果

## 自動検証

`dotnet run --project tests/JTCStamper.Checks -c Release`

実行結果はTEST-RESULTS.txtを参照。対象: IDの一意性、表示日付と生成日時の分離、注釈で原記録が変わらないこと、再起動後の検証、同時起動拒否、HMAC改変、異なる鍵、中間削除、一時ファイル、保存失敗前後、クリップボード失敗。クリップボードは偽物を注入するため、Windows APIの動作検証ではない。

## Windowsでの最小版受入試験（未実施）

1. Windows 11 / .NET 10 SDKでrun.cmdを起動。初回鍵作成と2回目起動を確認。
2. 氏名・下段を変更。1900年と2100年の日付、うるう日、不正日付、空欄を確認。
3. PNGコピー後にペイント、Word、Excel、PowerPointへ貼付。透明背景・赤色・寸法・文字を確認。形式指定貼付と通常貼付を分ける。
4. アプリを終了してから再度貼付。クリップボード形式PNGとBitmapの存在を確認。
5. 同じ印面を2回生成しIDが異なること、履歴時刻と表示日付が別であることを確認。
6. 履歴を選び注釈追記、再起動して保持を確認。原本保存のID・HMACを確認。
7. テスト用Windowsユーザーの保存フォルダーで書込み拒否、クリップボード競合、ディスク不足を再現。成功表示をしないことを確認。
8. テスト用履歴の中間レコードを書換・削除し起動拒否。鍵を退避して新規作成されないことを確認。実運用履歴で破壊試験しない。
9. 二重起動で2つ目が履歴を変更しないことを確認。

## 正規画像の復号率

氏名・文字量・日付・字体・サイズ・符号を分けた学習/調整セットと独立評価セットを作る。同一原画像の位置ずれを独立標本とみなさず、原画像単位で分割する。PoCの216件は製品の受入試験へ流用しない。

評価条件: 88/66/44px、PNG、JPEG品質、追加回転、非等方拡縮、余白変更、背景色、Office各経路、PDF、印刷スキャン。最初は手動切り出し、後でページ中探索を別評価する。

記録指標: 総数、領域検出成功、品質棄却、正しい符号、誤符号、候補数、正しいイベントが候補に含まれる率、最終結果。復号率の分母は全正規入力とし、受理済みのみの率も補助値として別記する。判定不能を分母から黙って除外しない。

## 模倣画像の誤受入率

独立に作った水平線の日付印、近いフォント、同じ氏名と日付、境界角度、意図してコードを真似た画像、別コードの画像、印影でない赤い図形を負例とする。正規画像の無断コピーは対象外として別群にする。

誤受入率 = 最終結果が「一致する生成履歴あり」となった模倣画像数 / 評価した模倣画像総数。判定不能率と「一致記録なし」率も併記。符号の最寄り分類成功を真正判定として集計しない。履歴件数とコード衝突率ごとに評価し、履歴に候補が多い状況を含める。

閾値は調整セットで凍結後、独立評価で測る。二項信頼区間と原画像単位の依存性を報告し、誤受入0件でも率0を保証しない。製品目標値は実験後に決め、未測定の12-bit実現性や誤受入率を広告しない。

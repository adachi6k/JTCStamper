# 幾何コード：12ビットの円周の欠け（試験実装）

現在の新規生成は12ビット（4096通り）。現在の12ビット形式のみを描画・照合します。短いコードは候補検索用で、認証や一意なイベントIDではありません。円周に短い透明な欠けを設けます。内側の目盛りをなくし、文字の収まる半径を36から41設計単位へ戻して拡大しました。旧印影の見た目や署名対象は書き換えません。

## 保存と描画

- 描画方式 `wpf-v5-gap12`、`Stamp.GeometryCode` は0～4095。
- GUIDの `.NET Guid.ToByteArray()` に対するSHA-256の先頭2バイトをリトルエンディアン整数にし、下位12ビットを使用。
- 円周の28セルに「1なら欠け、0なら連続した線」を描画。構成は形式・方向マーカー8ビット（0xD3）、ペイロード12ビット、CRC-8の8ビット。付加情報を除いた識別情報は12ビットです。
- CRC-8は多項式0x07、初期値0。形式マーカー、高位4ビットを入れたバイト、下位8ビットの順で計算。暗号学的認証ではなく誤読検査です。
- 96単位の設計座標で円中心(48,48)、半径43。円の線幅1.1、欠けの角度幅3.5度（直径88pxで約2.7px）。白で塗りつぶさず円弧を分割するため、欠けは透明です。37～143度と217～323度に各14セルを置き、円の外には出しません。正の角度は画面の下方向。
- 区切り線の傾きはコード下位桁に応じた描画上の変化として維持します。角度から短いコードを読む処理はなく、復号は円周の欠けだけを使用します。
- 完全なイベントID、表示日付、実生成時刻、PNGハッシュ、コードをHMAC保護された生成記録と原本に保存。保存失敗時のコピー抑止は従来どおり。

12ビットなので履歴間の衝突は起こります。複数候補を表示し、最新1件へ勝手に決めません。

## 復号

元画像から赤い円形印を探すか、手動で囲んだ領域を使います。入力は1200万画素・32 MiB以下。文書全体を2048pxへ縮小してから解析する処理は廃止し、元の解像度を保ちます。探索だけは複数縮尺で欠けた円の断片を結合し、元画像の赤画素から範囲を求めます。円内の閉じた文字を重複候補から除きます。選択範囲のみ赤色強度へ変換して復号します。

円周の欠けを±8度の範囲で0.25度刻みに読み、中心位置±0.5pxも探索し、半径42.2～43.8設計単位の赤色強度の最大値と既知のマーカーによる濃淡基準・各セルの境界余裕・CRCを確認します。回転候補から複数の値が得られた場合は確定しません。履歴にあるコードや正解値を復号器へ入力して補正することはありません。

12ビット読取の最低直径は80px、縦横比の差は4%以内。条件を満たしても読める保証はありません。小さい画像・圧縮・ぼけでは判定不能が起こります。

12ビットが読めればコードの完全一致で絞り込みます。読めなければ判定不能とし、類似検索だけを続けます。短いコードへのフォールバックや非対応形式の再描画はありません。絞り込みはチェックボックスで解除できます。非対応形式の原本は拒否し、生成履歴の非対応記録は照合対象から除外します。履歴全体のHMACは引き続き検証し、保存済みの鍵・記録は自動削除しません。

原本・生成PNGの完全一致とは区別し、加工画像では、コードと形の候補が見つかれば「対応する生成履歴候補あり」と表示し、生成元の未確定を別に説明します。コードとCRCは模倣できます。本物の無断コピーも区別できません。

## 実施済みの検証

1. 4096値すべての符号化→復号、各値の28セルを1つずつ反転した114688ケースの棄却。
2. Coreの独立した面積サンプリング画像：6値×88/176px×−4/0/4度の36条件で36/36正解。欠けなしの線のみ・空画像・小さい画像は12ビットとして確定しないことを確認。
3. Pillowで別実装した文字入り合成画像：2氏名×6値×2サイズ×3回転×3画素位置×PNG/JPEG品質80の432条件。**正解430、判定不能2、誤コード0**。内訳は次表。欠けなしの対照72条件は12ビット分類0。これは模倣全般の誤受入率ではありません。

| 円の直径 | 形式 | 正解 | 判定不能 | 誤コード |
|---|---|---:|---:|---:|
| 88px | PNG | 108/108 | 0 | 0 |
| 88px | JPEG 80 | 106/108 | 2 | 0 |
| 176px | PNG | 108/108 | 0 | 0 |
| 176px | JPEG 80 | 108/108 | 0 | 0 |

合成画像の氏名はJTC/田中、表示日付は'26.09.18、下段は(印)。12ビット値は0、1、0x555、0xAAA、0xABC、0xFFF。回転は−4/0/4度、画素位置は−0.35/0/+0.35pxです。同一画像からの派生で、独立した実運用標本ではありません。全4096値の画像耐性を保証する試験でもありません。読み取り閾値は暫定値です。

幅2.5度も同じ合成条件で試し、正解358/432でした。3.5度を採用し、探索範囲の取りこぼしも修正しました。このデータを使って調整しているため、独立した評価用データでの性能ではありません。コードにより欠けの数が変わり、多い場合は破線に近く見えます。

## Windows・実画像の検証

WindowsバッチにWPF描画の72条件と無変調／コードを模倣した対照を追加しました。`ring12-<phase>.json`に正解・誤コード・判定不能と対照を別集計します。Windows実行ができないため、この試験はまだ未実施です。WPF・Office・EMF・印刷・スキャンの実画像精度や、模倣画像の誤受入率は未評価です。符号を再現した模倣が読めることはあり、CRCを認証に読み替えてはいけません。

## 合成画像評価の再現

Pillowと.NET 10 SDKが必要です。アプリ自体に追加のPython依存はありません。

```text
python experiments/fixtures/Generate-Ring12Fixtures.py <作業フォルダー> <YuGothR.ttcなどフォントのパス>
dotnet run --project experiments/JTCStamper.ImageEvaluation -c Release -- <作業フォルダー>/manifest.json <結果JSON>
```

生成器は画像・画素データを作業フォルダーへ書きます。評価ツールは結果をJSONへ書き、誤コードが1件でもあれば終了コード1です。終了コード0でも判定不能が含まれるため、集計を必ず確認します。Windows描画の評価はscripts/Invoke-WindowsSmoke.ps1で別に実行してください。

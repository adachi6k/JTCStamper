# 円周コードのアルファブレンディング比較

## 結論

円周コードの欠けを不透明度30%・50%・70%で埋めると、円がつながって見えます。しかし、今回の半径・線幅・符号配置と読み取り方法では、小さいJPEGでの復号が悪化しました。現時点では製品の完全な欠け（不透明度0%）を維持します。30%はPNGを保つ用途の次の実機評価候補ですが、本採用の根拠はまだありません。今回の変更は評価コードと報告書のみで、配布EXE・履歴・鍵・現行レンダラーは変更していません。

これはアルファ方式全般が不可能という結論ではありません。別の濃淡配置、線幅、背景補正や読み取り方法は未評価です。

## 方法

- 独立したPillow描画。円周のコード部分だけ不透明度0/30/50/70%、それ以外の円・文字・区切り線は不透明。元の12ビット、マーカー8ビット、CRC8ビット、欠け幅3.5度を維持。
- RGBAで描き、背景に合成してからRGBへ変換。8倍の合成画像を縮小し、PNG相当またはJPEG品質80を評価。読み取り側にアルファ値・正解コード・履歴候補は渡さない。
- 白背景は氏名JTC/田中、6コード（0/1/0x555/0xAAA/0xABC/0xFFF）、直径88/176px、回転−4/0/4度、画素位置−0.35/0/+0.35px、PNG/JPEGの432条件／不透明度。
- 黄(255,248,210)・青(215,235,255)・灰(210,210,210)・黒文字(40,40,40)・赤文字(170,35,35)の背景は氏名田中、画素位置+0.35pxで、それぞれ72条件／不透明度。
- 各不透明度で符号付き792条件、符号なしの連続円132条件。合計3,696条件（符号付き3,168、対照528）。対照は不透明度間で同じ画像を繰り返しており、独立標本ではない。
- 生産用の読取器（Baseline）と、マーカーの濃淡条件のみを緩めたExperimental、Sensitiveを比較。輪郭探索・CRC・セルの余裕条件・複数コードなら棄却する条件は共通。
- 濃淡条件は「高濃度−低濃度の下限／低濃度÷高濃度の上限」：Baseline 0.12/0.50、Experimental 0.08/0.85、Sensitive 0.03/0.95。全不透明度・全背景に同じ設定を適用。Sensitiveは最初のJPEG失敗を見て追加した探索的な調整で、独立した検証用データではない。

## 白背景・88pxの読み取り

各セルは「正しいコードを復号した件数／108件」。Sensitiveは製品へ適用していない実験設定です。

| 不透明度 | 製品の判定：PNG | 製品の判定：JPEG80 | Sensitive：PNG | Sensitive：JPEG80 |
|---|---:|---:|---:|---:|
| 0% | 108/108 | 106/108 | 108/108 | 106/108 |
| 30% | 108/108 | 0/108 | 108/108 | 26/108 |
| 50% | 72/108 | 0/108 | 108/108 | 9/108 |
| 70% | 0/108 | 0/108 | 88/108 | 0/108 |

## 背景を含む全条件

各行の符号付き画像は792件。正解・判定不能・誤コードを分けて表示します。

| 不透明度 | 読取設定 | 正解 | 判定不能 | 誤コード |
|---|---|---:|---:|---:|
| 0% | Baseline | 662 | 130 | 0 |
| 0% | Experimental | 666 | 126 | 0 |
| 0% | Sensitive | 666 | 126 | 0 |
| 30% | Baseline | 527 | 265 | 0 |
| 30% | Experimental | 539 | 253 | 0 |
| 30% | Sensitive | 565 | 227 | 0 |
| 50% | Baseline | 267 | 525 | 0 |
| 50% | Experimental | 520 | 272 | 0 |
| 50% | Sensitive | 529 | 262 | 1 |
| 70% | Baseline | 0 | 792 | 0 |
| 70% | Experimental | 352 | 440 | 0 |
| 70% | Sensitive | 353 | 439 | 0 |

符号なし対照は全設定でコード分類0件でした。ただし、これは模倣画像の誤受入率でも暗号学的認証の評価でもありません。

Sensitiveの不透明度50%では、88px・回転0度・画素位置+0.35px・黒文字背景・JPEG品質80の1件で、正解0x555を0x7FAと誤読しました（fixture 02631.bgra）。CRCを通る誤読が起きることを実際に確認したため、この設定を製品へ採用していません。

赤文字背景は全設定・全不透明度で正解0/72件です。印影と背景の赤い文字が同じ探索対象になり、不適切な候補範囲や読み取り失敗が発生します。半透明化だけでは解決しません。色付き背景や黒文字背景でも範囲推定や濃淡の影響があり、背景別・サイズ別の詳細はALPHA-VALIDATION.jsonを参照してください。

## 確認範囲と次の判断

全3,696条件×3設定を実行し、整理した再現用評価器でも先の結果と全件一致しました。PNGの円周上の画素が指定したアルファ値になることも確認しています。

Windows WPF・Office・EMF・印刷・スキャンでは未実行です。全4096コードの画像耐性、任意背景、任意サイズ・回転、模倣画像の誤受入率を保証するものではありません。欠け方式の430/432件は白背景だけの値であり、背景を含む実運用の精度とは区別してください。

次にアルファ方式を進める場合は、30%案を実際のWPFから出力してPNGを保つ貼付経路で確認し、88px JPEGへの対応には濃淡の置き方や線幅も含めて再設計する必要があります。低い濃淡差を無条件に受け入れるだけの調整は、今回誤コードが出たため採用しません。

## 再現

.NET 10 SDK、Python＋Pillow、Yu Gothic Regularのフォントファイルが必要です。PNG生成にはWPFを使いません。元の比較対象CoreはGitコミットad601a0です。正確なソースハッシュはJSONに保存しています。

```text
python scripts/Generate-AlphaFixtures.py <作業フォルダー> <YuGothR.ttcのパス>
dotnet run --project tests/JTCStamper.AlphaEvaluation -c Release -- <作業フォルダー>/manifest.json <結果JSON>
```

生成器は約850MBのBGRAデータとプレビューを作業フォルダーに出力します。評価器の終了はベンチマークの完了を意味し、安全性の合格ではありません。JSONのWrong・Unreadable・ControlClassifiedを確認してください。製品の動作やデータ保存先は変更しません。

# 画像からの印影照合

［照合］タブでPNG・JPEG・BMP・単一ページTIFF、原本（.jtc）を選択できます。クリップボードのPNGとBitmapにも対応します。照合先は［履歴］で選択中の保存先です。候補を選択して履歴を開けば注釈を確認できます。照合で履歴を書き換えません。

## 画像内の印影を探す

ファイル全体が生成PNGと完全一致しなければ、赤い画素から円形印を検出します。画像に複数の印影がある場合は領域の一覧から選びます。青枠で比較範囲を表示します。自動検出できない場合は画像上で印影をドラッグして囲んでください。円の外周を含め、他の赤文字を入れずに指定してください。

新しい生成記録には生成時のPNG本体を含め、記録のHMACとPNGのSHA-256を確認して比較用画像にします。画像本体がない既存履歴は上段文字・表示日付・下段文字を再描画し、PNGのSHA-256が生成記録と一致する場合だけ使用します。フォントや過去レンダラーの違いで再現できない記録は除外し、件数を画面に表示します。履歴のHMAC検証に失敗した場合は候補を表示しません。

赤い印影を96×96に正規化し、±8度を1度刻みで比較します。外周を除く文字・線の対称的な近傍一致度が0.72以上の候補を抽出し、下記の対応スコア順で上位8印面の履歴を提示します。0.72は候補抽出専用の暫定値で、表示スコアの足切りではありません。同点は従来の形比較で並べます。同じ印面に対応する複数イベントはそれぞれ表示します。

## 結果の意味

「確認できたこと」「この結果の意味」「次に確認すること」を分けて表示します。候補が得られたことと、生成元が確定したことを同じ扱いにしません。

| 状態 | 主表示 | 読み方 |
|---|---|---|
| 元PNG・原本の完全一致 | 一致する生成履歴あり | PNG全体、または原本の認証情報・記録ID・内容が記録と一致。PNGに対応する記録が複数なら1件に断定しない。 |
| 読取コードと形の両方に合う候補あり | 対応する生成履歴候補あり | 読み取りと候補検索は成功。完全一致ではないため、どの生成時の画像かは未確定。 |
| コードを読めないが、形の候補あり | 形が似た履歴候補あり | 形だけを手がかりにした候補。コード一致とは説明しない。 |
| 絞り込みを外し、コードが違う候補あり | 形が似た履歴候補あり | 候補ごとに「コード不一致」と表示。コード一致の候補と混在する場合も件数を分ける。 |
| コードは読めたが形の候補なし | 今回の検索では履歴候補なし | 同じコードの記録の有無も説明。比較対象外や画像変化を含み、偽造とは断定しない。 |
| コード未読取・形の候補もなし | 照合の手がかりが不足しています | 低解像度などの読み取り失敗と、履歴がない場合は区別できない。範囲指定・元画像・保存先を確認する。 |
| 比較用の印影がない | 比較できる生成履歴がありません | 記録がないか、再現できる印面がない。比較をしていないので不一致と扱わない。 |
| 読み込み・履歴の検証失敗など | 照合を完了できませんでした | 一致・不一致は判断していない。理由と次の操作を示し、候補を消す。 |

原本の認証情報は確認できても選択中の保存先に記録がなければ、「この保存先に一致する生成履歴はありません」と表示します。別の保存先の記録の有無は判断しません。

内部の完全一致判定（Match/NoRecord/Indeterminate）は維持しています。画像の類似候補をMatchへ昇格させる変更ではなく、画像の読取・検索で確認できた事実に応じて表示を分ける変更です。

### 履歴との対応スコア（暫定）

配点は上段文字・日付・下段文字の形が各最大0.100、読み取れたコードと履歴のコードが一致すれば0.700です。文字だけの一致は最大0.300になります。未読取は「未確認」、読み取った別コードは「不一致」と表示し、いずれもコード加点は0です。位置マーカー・CRCを通過した読取結果だけを使い、部分一致、CRC、冗長ビットを独立加点しません。連続した読取信頼度の評価はありません。

回転は従来の内側全体の形比較が最大になる角度を共通に使い、正規化画像の上段文字（y=2〜28）・日付（35〜60）・下段（67〜93）を個別比較します。中心から半径40未満に限定し、横線付近を除きます。各領域の赤画素について相手の1画素近傍に赤がある割合を双方から求め、調和平均を計算します。いずれかが30画素未満なら加点0（空白同士も0）。各値を10で割って文字の配点にします。領域分割は現在のレンダラー用です。

候補ごとに合計、文字の小計と3領域の内訳、埋め込み情報の得点と読取状態を表示します。小数点以下3桁に丸めます。OCRではないため、文字の意味の一致とは断定しません。

1.000でも原本・PNG全体の完全一致や真正性を証明しません。同じ文字・同じ短いコードの別イベントも同点になり得ます。配点は暫定で確率として校正しておらず、判定ステータスの昇格には使いません。詳しい説明は［対応スコアの配点と限界］にあります。

合成画像の自動テストで日付だけの違い、文字一致でコード未読取／不一致／一致、同じコードの複数候補、空画像、コード一致を優先する順位を確認しました。実際の上段文字・一桁違いの日付を含む印影、JPEG、Office、模倣画像でのスコア分布・誤受入率の校正は未実施です。

対応する印影は現在の12-bit形式とプレーン形式です。コードが読めれば同じコードで候補を絞り、読めなくても形の検索を続けます。非対応の原本は拒否し、非対応の生成記録は照合対象から除外します。履歴全体のHMAC検証は行い、記録や鍵は自動削除しません。候補は生成時のPNGを再現できる記録だけに対応付けます。領域や絞り込みを変更したときも履歴の検証をやり直します。コードの一致・類似候補からイベントIDを復元できたと扱わず、無断コピーの検出や偽造の断定もしません。

## 制限・検証

入力上限は画像32 MiB・1200万画素、原本1 MiB。画像は元解像度を保って解析し、選択範囲のみ幾何コードを復号します。自動検出の最小径は28pxで、赤色・ほぼ円形・円周が十分に見えるものが対象です。白黒、強い傾斜、欠け、他の赤線と重なる印影、極小画像は自動検出に失敗し得ます。手動範囲指定でも情報を復元することはできません。PDFそのものと複数ページTIFFは対象外です。

比較は直近300種類の印面、領域表示は先頭30件まで。対象外の件数・制限は画面に表示します。

Coreの合成画像で複数印影・サイズ違い・赤い四角形の除外・候補順位・空画像・透明画素をテストしました。WPFで描いた印影を96pxで文書に配置し0度/4度・JPEG品質85で検出するWindowsバッチ試験も追加しましたが、この環境ではWindows実行ができず未実施です。Office・実スキャン画像の精度、正規画像の復号率と模倣画像の誤受入率は未評価です。幾何コードの試験実装・暫定棄却条件・検証範囲はRING12-CODE.mdを参照してください。

## タブでの操作

メイン画面の［照合］タブ、またはメニュー［照合］→［照合タブを開く］を使用します。［作成］［照合］［履歴］の切替では入力・画像・照合結果を保持します。［選択した生成履歴を開く］で履歴タブの該当記録へ移動します。履歴追加後は［再照合］で保持している入力画像・原本を最新の履歴と照合できます。履歴保存先を変更すると照合画面を新しい保存先に切り替えて初期化します。照合処理中の保存先変更は完了後に行います。

表示用の状態分岐をCoreの自動テストで確認しています。コード不一致の候補、コード未読取、候補なし、比較対象なし、複数の完全一致、原本検証失敗を区別します。今回の画面配置についてWindows上の実機確認は未実施です。

## 表示と履歴の削除

ナビゲーションは「印影を作成」「印影を照合」「生成履歴」で画面見出しに統一しています。ナビゲーションのフォーカス枠は出さず、選択位置は背景と左側のアクセントで示します。照合結果は対応スコア付き候補を説明より先に表示します。

［履歴］→［現在の保存先の生成履歴をすべて削除…］は保存先と件数を確認後、生成・コピー・注釈の全記録を削除します。確認の初期選択はキャンセルです。鍵・印面設定・別途保存した画像や原本は残ります。削除は元に戻せず、削除後は照合画面も初期化します。照合処理中は削除できません。削除は新しい記録から行い、失敗時は一部削除の可能性を通知します（残存記録は連鎖の先頭部分）。個別削除は対象外です。

検出印影はプレビュー下の左右矢印または一覧で切り替えます。先頭・末尾では該当方向を無効にし、処理中も矢印を無効にします。手動選択後は右で先頭、左で末尾へ戻れます。生成履歴の保存先は［読取・検索の詳細］内に表示します。画像自体の保存先ではありません。

サイドバー上のメニューマークで折りたたみ・展開を切り替えます。折りたたむとアイコンだけになり、ツールチップで名称を確認できます。画面の入力状態を保持したまま幅だけが変わります。折りたたみ状態は起動をまたいで保存しません。

## プレーンモード・履歴画像・候補カード

［プレーン印影（幾何コードを埋め込まない）］では円を連続した線、上下の横線を水平に描きます。透明画素や余白も含め、画像にイベント情報を埋め込みません。プレーン設定は印面設定ファイルにも保存します。イベントID・生成日時・コピー記録・HMACは通常どおり保存します。短いコードを使えないため画像の形だけでは最大0.300ですが、元PNG・原本の完全一致確認は別に行えます。同一のプレーン印面を繰り返し生成すると同じPNGになるため、複数履歴が対応します。

新しい生成記録のPngBase64に生成時のPNGを保存します。この画像もHMAC保護の対象で、記録保存が終わるまでコピーしません。履歴は画像の分だけ大きくなります。バックアップ・移行・全削除は従来のjournal単位の操作に含まれます。既存記録は書き換えず、画像がないものは生成時のハッシュに一致する再現画像のみを表示します。

直近3件にはサムネイル、生成履歴画面には選択した記録の画像を表示します。表示項目は表示日付→上段文字→下段文字→実生成日時の順です。保存画像か再現画像かを表示します。

照合画面はスコアの高い順に最初の1候補を表示し、他の候補を前後ボタンで切り替えます。同点の場合も1件へ確定せず、件数と切替を残します。スコア44px、状態19px、日付・文字18pxのカードとし、内訳・記録IDは詳細欄に格納します。実数値が1.000の候補は緑のOK、中間は黄色の注意、検索で候補なしは赤い×です。赤は偽造判定ではありません。読取・比較不能は黄色の判定不能にし、候補のない状態で数値0を捏造せず「—」と表示します。原本・PNG全体の一致は緑の「一致」とし、暫定スコアと区別します。丸めると1.000になる未満の数値は「< 1.000」と黄色で表示します。

Windows実機の新しい描画・操作試験は未実施です。バッチスモークにはプレーン円周、生成画像表示、再現ハッシュ不一致の拒否を追加しています。

## 照合の中止

重い照合は［照合を中止］で取り消せます。処理が戻るまで少し時間がかかることがあります。中止した場合は結果を確定せず、履歴は変更しません。［再照合］で同じ入力をやり直すか、別の画像を選択してください。照合中の保存先変更と新しい照合は受け付けません。画面の切替は可能で、終了後に遅い結果を反映しません。

## キーボード操作の範囲（初回プレビュー）

自動検出した印影は一覧と前後ボタンをキーボードで選択できます。画像上をドラッグする手動範囲指定はマウス専用で、座標をキーボード入力する機能は初回プレビューにありません。キーボードだけで操作する場合は、画像編集ソフトで円全体と少しの余白を含む画像へ切り出してから、ファイルを開いて照合してください。自動検出できない画像ではこの方法でも照合できない場合があります。

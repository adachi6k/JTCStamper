# 1.0.0 MSIX 追加受入記録（2026-11-10）

[先行する13項目の実機試験](ACCEPTANCE-MSIX-1.0.0-2026-11-10.md)に続き、既存版からの移行と、別パッケージIDを継承した外部EXEの動作を確認した。**復元4通りとID継承の試験はすべて合格**。製品コードの修正は発生していない。

## 対象と範囲

- 記録コミット `c3db4c1ba08975e153bc45a35d1c386af4a1d751` をmainへpushし、[Windows CI run 42644745865](https://github.com/adachi6k/JTCStamper/actions/runs/42644745865)の `msix`、`smoke`、`migration-export`、`migration-import` がすべて成功した。
- 今回はそのCIのartifact `13687106052` から取得したTest用MSIX `1.0.0.0` を使用した。EXEのSHA-256は `78B972BE2D64CC3B18C2565CC31E7D0A5388FD2DCB260F299F346B5ADCBE2735`。先行試験の `195af78` から `c3db4c1` までの差分は文書だけ。
- Windows 11 Pro build 26200、x64。同じWindowsユーザーで架空のデータを作成し、アプリの画面操作で保存・復元した。
- Setup版の移行元には、既存インストールの0.2.1 EXEだけを専用フォルダーへコピーしたものを使用した。既存の個人履歴は使用していない。Setupインストーラーの新規導入・再インストールを試験したものではない。

## 0.2.1から1.0.0 MSIXへの移行

各移行元で印影1件、用途メモ、追記注釈2件を作成した。生成・コピー・注釈の計5レコード、鍵、Darkテーマがアプリ再起動後にも保持されることを確認してから、原本・印面設定・2種類のバックアップを保存した。

| 移行元 | バックアップ | 結果 | 鍵の扱い |
|---|---|---|---|
| Setup版EXEの隔離コピー | 移行用 `.jtcportable` | 合格 | 復元先のWindowsユーザーで再保護 |
| Setup版EXEの隔離コピー | 同じユーザー用 `.jtcbackup` | 合格 | DPAPI保護済み鍵を保持 |
| 公開済み通常版ZIP | 移行用 `.jtcportable` | 合格 | 復元先のWindowsユーザーで再保護 |
| 公開済み通常版ZIP | 同じユーザー用 `.jtcbackup` | 合格 | DPAPI保護済み鍵を保持 |

4通りすべてで以下を確認した。

- AppData外に新しい復元フォルダーを作成し、アプリが履歴の認証・検証完了を報告した。元の履歴5レコードのSHA-256も一致した。
- 復元先を開き、用途メモと追記注釈2件を画面で読み取れた。MSIX側でさらに1件追記し、注釈3件の永続化を確認した。
- ［原本を保存］で再保存した `.jtc` は移行元の原本と全バイト一致した。内部の384×384 PNGも記録済みSHA-256と一致した。
- 保存しておいた `.jtcstamp` を明示的に読み込み、上段・下段の文字が一致した。
- ［履歴 → 既定の保存先を使用］でMSIXのLocalStateに戻った。
- 移行元の隔離フォルダーにある鍵・履歴・テーマのハッシュは変わらなかった。

現在の製品機能は、注釈の**追記**と、PNGを含む**原本 `.jtc` の保存**。既存注釈を変更する機能やPNG単独の書き出し機能は、この試験の対象となる画面操作にはない。先行記録の未確認事項と手順書の表現を、この実際の操作に合わせて明確化した。

## 別パッケージIDを継承した外部EXE

専用の `JTCStamper.IdentityHost.C3DB4C1` パッケージを用意し、`Invoke-CommandInDesktopPackage` でAppData外の1.0.0 EXEを起動した。実行プロセスが `JTCStamper.IdentityHost.C3DB4C1_4yx9289nrzz4j` のIDを持つことをWindows APIで確認した。

- 通常起動で作成した鍵・履歴・Darkテーマを読み込めた。ファイルのSHA-256と画面のテーマ表示を確認した。
- 別フォルダーを選択した後、［既定の保存先を使用］でEXEと同じフォルダーに戻った。
- 注釈1件と印影1件を追加し、外部フォルダーに履歴計7レコードを保存した。元の鍵・テーマ・既存3レコードは変更されなかった。
- 継承元パッケージのデータ領域全体に、`key.dpapi`、`appearance.json`、`journal`内のファイルが作られていないことを確認した。
- パッケージIDなしで通常起動し直しても、追加後の履歴2件を読み込めた。

これは同コマンドを使用し、実際のパッケージIDを確認した条件での結果であり、任意の親アプリや権限構成すべてを検証したものではない。

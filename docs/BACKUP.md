# 履歴のバックアップと復元

## 現在提供する範囲

［履歴 → 履歴をバックアップ（同じWindowsユーザー用）］で`.jtcbackup`を保存します。
鍵、生成・コピー記録、保存画像、追記済み注釈を一つのファイルにまとめ、Windows DPAPI CurrentUserで全体を暗号化します。履歴のHMACと保存画像のハッシュを検証してから保存します。保存の途中で失敗した場合は既存バックアップを置き換えません。

この形式は**同じWindowsユーザープロファイルとDPAPI保護環境を保った状態での復旧用**です。同じユーザー名でアカウントを作り直すこと、Windowsを再インストールすること、別PCへコピーすることでは復元できる保証がありません。WindowsユーザープロファイルとDPAPIマスターキーを失った場合の復旧手段にはなりません。パスワードは入力しません。

印面設定ファイル(.jtcstamp)、appearance.json、履歴へ追記する前の注釈は含めません。これらが必要な場合は設定を保存・注釈を追記してから、設定ファイルを別途保管してください。現在は256 MiB以内のバックアップに対応しています。処理はメモリ上へ展開するため、大量履歴の性能は別途検証が必要です。

## 復元

1. ［履歴 → 同じWindowsユーザー用バックアップを復元…］でファイルを選ぶ。
2. 復元フォルダーを作る親フォルダーを選ぶ。
3. 表示された新しいフォルダー名を確認して復元する。
4. 完了後、必要なら［履歴 → 保存先を選択］で復元フォルダーを開く。

既存の履歴や現在の保存先は自動で上書き・変更しません。内部の一時フォルダーでHMAC連鎖、記録の順序、現行形式の保存画像ハッシュ、鍵の保存を確認してからフォルダー名を確定します。破損・異なる鍵・書込失敗は復元失敗です。現行形式以外の記録も改変せず保持しますが、画像照合に対応していると保証するものではありません。

通常の失敗では一時フォルダーを削除します。プロセス強制終了や削除権限の問題がある場合、選択した親フォルダーへ`.jtc-restore-*`が残ることがあります。これは未確定の復元データであり、成功と扱いません。復元先の確定済みフォルダーや既存履歴を、未確定データの掃除で削除しないでください。

バックアップに収録した範囲より後の生成・注釈は復元されません。HMACは、正規の古いバックアップへの巻戻しや末尾の削除を完全には検知しません。

## 別PC移行

preview.10から、［履歴 → 別PCへの移行用バックアップを保存…］で`.jtcportable`を保存できます。12文字以上の長く推測されにくいパスフレーズを2回入力してください。復元は［履歴 → 移行用バックアップから復元…］から行い、パスフレーズを入力します。復元先ユーザーのDPAPIで鍵を保護し直し、新しいフォルダーへ復元します。現在の保存先は自動では変更しません。

**パスフレーズを忘れると復元できません。リセット機能はありません。** バックアップとは別の安全な場所（パスワード管理ソフトなど）に保管してください。短い定型文・氏名・日付などから推測できるパスフレーズは避けてください。ファイルとパスフレーズを持つ人は履歴だけでなくHMAC鍵も取得できます。第三者へ渡さないでください。

Windows再インストールや元プロファイル喪失に備える場合は、元環境が利用できるうちに移行用バックアップを作成してください。既存の`.jtcbackup`を別PCに持っていくだけでは復元できません。どちらの形式も保持し、拡張子を変更して変換することはできません。[暗号方式・形式・検証方針](PORTABLE-BACKUP.md)を参照してください。

## 未保存入力

上段・下段・プレーン設定を変更したまま終了または別設定を読み込む場合、破棄するか確認します。日付は当日／例外指定の一時的な選択として扱い、日跨ぎなどで未保存警告を出しません。

未追記注釈は生成イベントごとに画面内で保持します。別の履歴を選んでも、そのイベントの注釈として勝手に転用しません。終了・保存先変更では未追記分の破棄確認が出ます。下書きは再起動後には残りません。

## 起動・保存の失敗時

処理中は進行表示が出ます。履歴を書き込む処理は同時に実行できず、コピーの連打や保存先の変更は受け付けません。処理中に閉じると、処理完了後に終了します。保存に失敗した場合は自動で閉じず、結果を表示したままにします。強制終了や電源断で同じ結果を保証するものではありません。

「成功扱いにしていません」と出た場合は、クリップボードに画像があってもコピー成功とは扱いません。コピーAPIの後に完了記録の保存が失敗する場合があるためです。履歴が「コピー未完了／不明」の場合、貼付できたことから記録の完了を推測しないでください。

鍵が見つからない、または読めない場合：

1. アプリを閉じ、現在の保存先フォルダーをそのまま別の場所へ保全します。key.dpapiやjournalを削除・書換えしないでください。
2. 生成履歴がある場合は、新しい鍵を作って復旧したことにはできません。同じDPAPI環境で読める既知の正常なバックアップ、またはパスフレーズが分かる移行用バックアップを、新しいフォルダーへ復元します。
3. 正常な鍵・対応するバックアップがなければ、既存履歴の認証を回復できません。新しい保存先で使い始める場合も、過去の履歴とは別の履歴になります。
4. 初回起動の失敗で生成履歴がまだない場合は、書き込める空のフォルダーを新たに選んで開始できます。失敗した保存先は調査のため保全してください。

鍵は一時ファイルへの書込・フラッシュ後に名前を確定します。中断時に残った.jtc-write-*.tmpをkey.dpapiへ手動で置き換えないでください。不完全なデータの可能性があります。部分書込例外、欠損鍵、破損鍵、書込先の競合に加え、共通の書込ヘルパーで鍵を部分書込した専用プロセスの強制終了と再開を検査しています。容量不足は別途、専用NTFS VHDを空き0バイトにして実際のエラー112を確認し、鍵・記録・原本・バックアップの保全と容量回復後の再開を検査しました。詳細は[容量不足試験](DISK-FULL.md)を参照してください。電源断・物理故障・OneDrive同期競合などの全条件を保証するものではありません。

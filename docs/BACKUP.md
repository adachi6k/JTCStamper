# 履歴のバックアップと復元

## 現在提供する範囲

［履歴 → 履歴をバックアップ（同じWindowsユーザー用）］で`.jtcbackup`を保存します。
鍵、生成・コピー記録、保存画像、追記済み注釈を一つのファイルにまとめ、Windows DPAPI CurrentUserで全体を暗号化します。履歴のHMACと保存画像のハッシュを検証してから保存します。保存の途中で失敗した場合は既存バックアップを置き換えません。

この形式は**同じWindowsユーザープロファイルとDPAPI保護環境を保った状態での復旧用**です。同じユーザー名でアカウントを作り直すこと、Windowsを再インストールすること、別PCへコピーすることでは復元できる保証がありません。WindowsユーザープロファイルとDPAPIマスターキーを失った場合の復旧手段にはなりません。パスワードは入力しません。

印面設定ファイル(.jtcstamp)、appearance.json、履歴へ追記する前の注釈は含めません。これらが必要な場合は設定を保存・注釈を追記してから、設定ファイルを別途保管してください。現在は256 MiB以内のバックアップに対応しています。処理はメモリ上へ展開するため、大量履歴の性能は別途検証が必要です。

## 復元

1. ［履歴 → バックアップから新しいフォルダーへ復元］でファイルを選ぶ。
2. 復元フォルダーを作る親フォルダーを選ぶ。
3. 表示された新しいフォルダー名を確認して復元する。
4. 完了後、必要なら［履歴 → 保存先を選択］で復元フォルダーを開く。

既存の履歴や現在の保存先は自動で上書き・変更しません。内部の一時フォルダーでHMAC連鎖、記録の順序、現行形式の保存画像ハッシュ、鍵の保存を確認してからフォルダー名を確定します。破損・異なる鍵・書込失敗は復元失敗です。現行形式以外の記録も改変せず保持しますが、画像照合に対応していると保証するものではありません。

通常の失敗では一時フォルダーを削除します。プロセス強制終了や削除権限の問題がある場合、選択した親フォルダーへ`.jtc-restore-*`が残ることがあります。これは未確定の復元データであり、成功と扱いません。復元先の確定済みフォルダーや既存履歴を、未確定データの掃除で削除しないでください。

バックアップに収録した範囲より後の生成・注釈は復元されません。HMACは、正規の古いバックアップへの巻戻しや末尾の削除を完全には検知しません。

## 別PC移行

現行形式では提供しません。別PC移行には、ユーザーが管理するパスフレーズによる鍵導出・認証付き暗号化と移行先でのDPAPI再保護が必要です。誤パスワード、破損、鍵のすり替え、旧形式の読込、パスワードを忘れた場合の説明を含め、別Issueで実装・検証してから提供します。

## 未保存入力

上段・下段・プレーン設定を変更したまま終了または別設定を読み込む場合、破棄するか確認します。日付は当日／例外指定の一時的な選択として扱い、日跨ぎなどで未保存警告を出しません。

未追記注釈は生成イベントごとに画面内で保持します。別の履歴を選んでも、そのイベントの注釈として勝手に転用しません。終了・保存先変更では未追記分の破棄確認が出ます。下書きは再起動後には残りません。

# バージョン規約（SemVer 2.0.0）

JTC Stamperの製品版番号は[Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)に従う。Directory.Build.propsのVersionを正とし、通常版とLiteは同じ版番号を使う。

## 互換性の対象

このアプリで版番号の判断対象となる公開インターフェースは、文書で提供を約束した生成・コピー・照合の機能、PNG等の出力形式、印面設定・原本・生成履歴・注釈・バックアップ/移行用バックアップの読み書き、既存データを保持する更新手順。内部クラスや試験専用CLIは公開APIではない。画面の配色や余白だけの変更は通常、互換性を壊す変更に含めない。

新しい版で既存データを読めなくする、利用者に手動変換やデータ破棄を要求する、提供済みの出力/機能を削除するといった変更は互換性破壊として扱う。透過的な移行により既存の利用契約を保つ場合は必ず移行試験で確認する。新しい版が作成したデータを旧版で読めるという前方互換性は一律に約束せず、戻せる条件を各リリースで明記する。保存形式のスキーマ番号は製品版番号と別管理で、版番号だけから読取可否を判断しない。

## 1.0.0以降

|変更|番号例|
|---|---|
|互換性を保つ不具合修正|1.2.3 → 1.2.4|
|互換性を保つ機能追加・公開機能の非推奨化|1.2.3 → 1.3.0|
|互換性を壊す変更|1.2.3 → 2.0.0|

MINOR更新ではPATCHを0、MAJOR更新ではMINOR/PATCHを0に戻す。公開済みの同じ版の内容は差し替えない。

## 0.xとプレリリース

0.xは初期開発で、公開インターフェースはまだ安定を約束しない。このプロジェクトでは0.x期間も、互換性を保つ修正をPATCH、新機能/互換性破壊をMINORへ反映し、互換性破壊は必ず変更履歴に明記する。0.xであることを、利用者のデータを予告なく失わせてよい理由にしない。

現在の0.1.0-preview.12は有効なSemVerで、0.1.0へ向けたプレリリース。公開前の正式版扱いへは変更しない。同じ対象版の次の公開プレビューは0.1.0-preview.13、候補確定時は0.1.0-rc.1、プレリリース期間を終えたときに0.1.0とする。0.1.0も1.0.0の安定契約を意味しない。安定した互換性を宣言できる段階で1.0.0へ進む。EMF等の追加機能を0.1.0公開後に追加する例は0.2.0（開発中は0.2.0-preview.1）。

プレリリース識別子の数値は数値として比較するためpreview.9 < preview.10。rcへの変更は候補段階を意味する。CIの実行回数だけで製品版番号を進めないが、一度公開したパッケージへ修正を加える場合は新しい版を割り当てる。内部の未公開候補はGitコミットとEXEのハッシュで区別する。

## ビルド・配布での表現

- 製品版番号/About/ZIPの識別: 0.1.0-preview.12。
- Gitタグ: v0.1.0-preview.12。先頭のvはタグの接頭辞で、SemVer本体には含めない。
- EXE ProductVersion: 0.1.0-preview.12+コミットSHA。+以降はビルドメタデータであり、新旧比較には使わない。
- .NET AssemblyVersion/FileVersion: SDKがVersionの数値部分から導出する4区切り形式（例0.1.0.0）。Windows/.NET用の技術情報であり、利用者向けのSemVerそのものではない。

Versionプロパティにはビルドメタデータを直接書かず、SDKによるコミット付与に一本化する。配布スクリプトは先頭ゼロ・空の識別子・余分な区切り等を拒否し、タグと製品版番号、EXEのProductVersionも照合する。構文検査だけでは変更内容に対するMAJOR/MINOR/PATCHの妥当性は判断できないため、公開前レビューで確認する。

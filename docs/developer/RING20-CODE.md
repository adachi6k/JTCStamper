# 20bitの履歴候補コード

開発版形式：wpf-v6-gap20。12bitの読み取り・履歴候補表示は削除し、保存ファイルの自動削除や再署名はしない。未対応レコードもHMAC連鎖検査の対象だが画像比較候補から除く。プレーン形式は継続。

- 同期0xD3（8bit）＋識別20bit＋CRC8＝36セル。最初の32セルを二つの円弧（37～143°、217～323°）に16セルずつ配置し、残り4CRCセルを上下線の±24位置に配置。
- 円弧の欠け幅3.5°。横線の欠け幅3.2設計単位。印影外側余白には埋め込まない。
- 下位2bitから上下線の相対角度差−3/−1/+1/+3°を決定。各線は半分ずつ逆方向に傾く。
- 識別値はイベントGUIDバイト列のSHA256先頭3byteをlittle-endianで整数化し、下位20bitを取得。重複回避割当は実装していない。
- CRC8はpoly0x07、init0。入力は0xD3、20、識別値の3byte big-endian。秘密鍵による認証ではない。
- 完全イベントID・生成時刻・用途メモ・PNGはGeneratedに保存しHMAC-SHA256で保護。画像コードの一致は履歴候補の根拠であり真正性ではない。

検出では複数スケールの包含候補がより円形（縦横差4%以内）になるとき、面積比1.5まで補足。元画素を改変せずに読取。線の濃さから角度と各線の上下位置を独立に推定し、コードの下位2bitと実測角度の一致を確認する。

単一候補は採用。複数候補は、9中心位置中6以上・2回転以上で支持される唯一の候補があり、競合する各候補の支持が1点だけの場合に限り安定候補を選ぶ。探索点は相関しており確率ではない。履歴や期待コードを復号に使わない。共有可変状態を持たず、キャンセルと画像上限を検査する。

15mm標準PDFの埋込画像・150/300dpiは製品Coreで各100/100。最小PDF（56px JPEG）は全条件0/100。近傍に赤い図形を置いた追加12例は全件成功。より多様な文書画像を網羅する保証ではない。WPF描画スモークは更新・ビルド済みだがWindows連携エラーにより実行未完了。
